# 開發計畫與協作方式

版本：1.0　｜　目前狀態：M0 已由 GitHub Actions 驗證；M1 核心帳號與區域協調已進入驗收。

## 1. 推進原則

先讓「同帳號同區限制」真正可用並經過並行測試，再擴充可配置介面。使用者負責大方向、遊戲規則與實際體驗；Codex 負責已授權範圍內的實作、驗證、文件與 PR。

- 每個 Issue 都引用 FR 與 AC 編號。
- 每個 PR 解決一個可說明、可驗收的行為；相關前後端及 migration 可在同個 PR 完成。
- 先驗證可重建環境，避免每次任務都重新猜安裝方式。
- 測試驗證功能與資料；預覽提供使用者操作。兩者都納入交付。
- 里程碑順序是建議執行順序，不要求為每個普通實作步驟另行請示。
- 本文件不承諾固定工程天數。M0＋M1 實測完成後，再依真正的環境及修改輪次估算後續。

## 2. 里程碑

### M0：Repository 與可重建環境

工作：

- 檢查 repository，建立 solution、前端與測試骨架。
- 固定 .NET、Node 及相容套件版本，提交 lockfile。
- 建立 bootstrap、dev、verify、package 腳本與設定範本，更新 README 的實際指令。
- 設定 Codex 環境準備流程，使 restore、npm 安裝及測試資料可重建。
- 建立 PostgreSQL 初始 migration 與虛構種子。
- GitHub Actions 執行 .NET／Vue 建置、型別檢查及 PostgreSQL service container 測試。
- 建立可識別版本的發布成果；預覽／正式連線設定分開。

完成條件：從乾淨環境依 README 能啟動 Web＋PostgreSQL，CI 有實際成功紀錄。不能只提交未驗證的 YAML 或空測試。

### M1：核心帳號與區域協調

工作：

- 暱稱工作階段、穩定參與者 ID；Admin 能力／投影先保留正確邊界。
- 帳號與卡片最小管理、所屬帳號、主要操作者與使用狀態。
- 固定 ID 的區域、預約、入場、回村與取消操作。
- Vue 看板拖曳及替代按鈕，後端結果才決定是否成功。
- PostgreSQL 帳號列鎖及核心命令交易；加入最小 AuditEvent 保存。
- SignalR 保存後同步，斷線提示及重連取得最新資料。
- 提供兩位普通使用者與一位 Admin 的虛構預覽資料。

完成條件：AC-001–AC-014、AC-023、AC-028 通過相關層級檢查，尤其 AC-008 必須真實並行。同帳號 A／B 競爭的錄影或測試 trace 可供查看。

### M2：可配置名稱、帶值標籤與資料表

工作：

- FieldDefinition、RecordFieldValue、SharedFieldValue、Collection／View 定義。
- 個別標籤、共通獨立值與共通共享值。
- 設定頁可改名、選項、順序、顏色、欄位顯示及視圖。
- 帳號密碼表直接文字顯示與明文保存；帳號關聯共用。
- 新建自由表格、表格儲存格編輯、基本篩選與排序。
- 核心綁定欄位與一般欄位的命令分流，刪除外觀不影響占用。

完成條件：AC-015–AC-022 與相關核心回歸案例。朋友能在設定頁改名稱，不必修改程式或重建資料表。

### M3：多人編輯存在感與衝突體驗

工作：

- 普通使用者在線名單、代表色、查看／編輯目標提示。
- 多分頁彙總、心跳清除與 Admin 隱身投影。
- 欄位級版本、草稿保留、最新值比較、共通值衝突處理。
- 重連訂閱／快照版本協調，定期版本校對。
- 隱身使用者造成的衝突不帶其身分。

完成條件：AC-019–AC-021、AC-025–AC-032、AC-056。兩個瀏覽器可操作同卡片不同欄位，同欄位不無聲覆蓋。

### M4：流程、04:00 資格、活動與累積所得

工作：

- 初始練等／任務／功勳／正式活動階段及可配置轉換。
- 任務道具數量、最後功勳值；不要求逐場勝負或固定日數。
- QualificationCycle、可注入 Clock、時區／換日快照。
- 分流、入場時間、退出及主要操作者的活動紀錄。
- 累積所得與 1:1 功勳兌換，包含原子操作及請求去重。
- 死亡後新一輪累積、TK 永久失格、封存與接替卡片。

完成條件：AC-033–AC-049、AC-057 及 AC-011／AC-012。驗證功勳兌換至 0 後仍保有已啟用資格，且不重複加幣。

### M5：Admin 日誌與全介面可見性核對

工作：

- Admin 專屬口語日誌頁、篩選與必要詳情。
- 後端日誌能力驗證與暱稱切換後的能力更新。
- 核對 REST、SignalR、presence、人數、最後編輯者、錯誤訊息及後續匯出路徑。
- 日誌保留歷史名稱與 Admin 操作；普通受眾只得到允許的投影。

完成條件：AC-024–AC-029、AC-050。此階段是全面核對，不代表 M1–M4 可以先對外洩漏 Admin 身分。

### M6：Windows 精簡面板

工作：

- Vue `/panel` 精簡視圖，重用欄位、名稱與同步。
- WPF＋WebView2、置頂、位置／大小、系統匣、顯示／隱藏快捷鍵。
- 個人篩選與欄位顯示設定，斷線與最後同步提示。
- Windows CI 發布安裝／可執行成果，處理 WebView2 runtime 需求。
- 遊戲視窗模式、DPI、多螢幕與失焦行為的實機驗收。

完成條件：AC-051–AC-052。瀏覽器與桌面使用同一份資料，不增加本地後端或資料庫。

### M7：發布、還原與多人試用

工作：

- 家中預覽與正式的獨立部署配置、Tailscale 私人入口。
- 建置成果與 commit 對應，可選部署代理取得指定版本。
- migration bundle／script、備份與還原演練。
- 約 4–5 位使用者完整操作，記錄需要調整的名稱與互動。
- 更新部署及日常操作說明。

完成條件：AC-053–AC-055，重要核心回歸檢查通過。正式發布依當次授權執行；設定發布流程不等於已授權發布每個未驗收版本。

## 3. 優先建立的 Issues

| 建議 Issue | 對應 | 主要交付 |
| --- | --- | --- |
| 建立可重建的 Web／PostgreSQL 環境與 CI | M0、FR-020 | 實際執行指令與成功 CI |
| 完成帳號區域預約與回村的交易規則 | M1、FR-001–FR-004 | API、資料模型、並行測試 |
| 完成最小協作看板與狀態同步 | M1、FR-016–FR-017 | 可拖曳介面與雙使用者證據 |
| 加入帶值標籤與共通範圍 | M2、FR-005 | 定義／值分離及跨卡片同步 |
| 建立可改名視圖、帳密表與自由表格 | M2、FR-006、FR-015 | 設定頁與普通文字欄位 |
| 加入在線編輯及隱身回應投影 | M3、FR-014、FR-016 | 多工作階段測試 |
| 完成資格換日與累積／兌換命令 | M4、FR-008–FR-010 | 邊界、原子性及去重測試 |

剩餘 Issues 在接近對應里程碑時拆分，避免一開始建立大量細碎工作卻忽略核心功能。

## 4. Issue 內容格式

```markdown
## 目的

目前哪個使用情境無法完成，完成後使用者能做什麼。

## 範圍

- 對應 FR：
- 對應 AC：
- 本次包含的行為：
- 已確定留待後續的工作：

## 驗收

- [ ] 指定情境的行為正確
- [ ] 涉及核心規則時，API 與資料庫結果一致
- [ ] 相關測試已實際執行並附結果
- [ ] 介面變更有可查看的成果
- [ ] 有資料變更時附 migration 與升級方式
```

## 5. 一般 PR 完成定義

- 行為符合對應 FR／AC，沒有未說明的範圍變更。
- 相關建置、型別與必要測試通過；未執行項目及原因如實列出。
- 沒有將核心限制移到只在前端執行。
- API 契約、畫面及資料版本一致。
- 新資料欄位與指令在需要時更新規格、migration 及腳本。
- 若影響可見介面，附虛構資料的畫面或預覽；若影響桌面行為，標示 Windows 實測結果。
- 不把未完成的核心保護隱藏在 TODO 後宣稱完成。

## 6. 預覽與正式使用

使用者可從私人筆電遠端連到家中查看，也可以在具備 Tailscale 連線時直接開啟網站。Codex 雲端執行與持續可連線的預覽主機是兩種環境；不把短暫工作環境當成正式主機。

GitHub Actions 先產生通過驗證的成果；預覽更新採指定分支或明確選定版本。正式資料庫不作為 Codex 的測試資料來源。介面上的「目前版本」可顯示 commit 短碼供核對，開發細節放在說明或診斷位置，不干擾日常操作。
