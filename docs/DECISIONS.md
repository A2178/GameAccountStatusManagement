# 決策紀錄與預設值

版本：1.0　｜　日期：2026-09-09

需求來源為此輪完整對話。使用者最後的明確指示優先於較早的建議。本文區分已確認事項與為了能開始開發而採用的可調整預設。

## 1. 已確認決策

| 編號 | 決策 | 影響 |
| --- | --- | --- |
| D-001 | 核心是同帳號多卡片不能同時占用不同野外區域 | 所有 API、表格、Admin 與未來功能都必須遵守 |
| D-002 | 沒有每日固定地區限制 | 回村並解除所有占用後，當天可切換不同區域 |
| D-003 | 可同時管理自己的與朋友的多個帳號 | 帳號擁有者、工具參與者與當前操作者分離 |
| D-004 | ASP.NET Core＋Vue＋PostgreSQL | 保留 .NET 後端，前端整合發布；無 Firebase 依賴 |
| D-005 | Code-First、SOLID、精簡 Clean Architecture | 規則可測試，避免 UI 直接寫核心狀態 |
| D-006 | 名稱、欄位、標籤、階段及視圖需彈性設定 | 固定 ID 與中性程式命名；不用顯示文字當鍵 |
| D-007 | 標籤必須可帶值 | 定義與每張卡片的值分離；共通作用範圍與值作用範圍分離 |
| D-008 | 所有人能即時看狀態及普通成員的編輯位置 | Vue＋SignalR；不必改回 Blazor |
| D-009 | 功勳達標後隔天才能投入，04:00 換日 | 保存資格里程碑與最早可投入時間 |
| D-010 | 成功進入後功勳可 1:1 換金幣 | 剩餘功勳與已啟用資格分離，兌換原子化 |
| D-011 | 金幣只記錄累積取得量，每角色獨立 | 不做支出餘額或裝備系統；保留可修正的累積紀錄 |
| D-012 | 死亡過多需重刷；TK 過多永久失格 | 明確資格輪次及永久旗標；封存舊卡片 |
| D-013 | 記錄目前分流與進入時間 | 使用活動紀錄避免上一場狀態誤留 |
| D-014 | 工具只需暱稱，不要密碼 | 伺服器簽發訪客工作階段，普通權限相同 |
| D-015 | 暱稱 Admin 才能看日誌，Admin 隱身 | 後端能力與可見性投影；不能只靠前端隱藏 |
| D-016 | 帳密表不要遮罩或資料欄位加密 | 按普通文字保存與顯示，不自行改回密文方案 |
| D-017 | 日誌使用非工程師可理解的口語描述 | 結構化事件＋名稱快照；Admin 操作亦記錄 |
| D-018 | 可加 Windows 桌面面板 | WPF＋WebView2，共用 Vue 與後端 |
| D-019 | 初期家中部署，筆電可遠端連回 | 不要求筆電架設完整環境；預覽與正式分開 |

## 2. 為開發採用的預設

這些預設可先實作，不需要再逐項向使用者確認；若影響實際遊戲判定，應在預覽驗收時核對。修改預設時同步更新產品規格及案例。

| 編號 | 預設 | 理由／核對時機 |
| --- | --- | --- |
| A-001 | 工作區時區 `Asia/Taipei`，24 小時制 | 使用者偏好繁體中文且位於台灣的既有背景；遊戲伺服器時區尚未明確確認，部署前核對 |
| A-002 | 共通標籤預設各卡片獨立值，可另選共享值 | 已獲使用者同意依討論彈性設計；避免職業等值被全體覆寫 |
| A-003 | 共通範圍預設主卡片資料集 | 涵蓋所有帳號角色，不把職業欄位自動加到帳密表 |
| A-004 | Admin 比對採 trim 後的大小寫精確字串 | `Admin` 特殊；其他大小寫仍為普通暱稱 |
| A-005 | 隱身隱藏活動與身分中繼資料，業務資料照常同步 | 核心協調優先；隱藏占用會使朋友誤入不同區域 |
| A-006 | 兌換由使用者回報，輸入正整數，可部分兌換 | 遊戲只確認比例及進場條件；不推定自動或全部兌換 |
| A-007 | 目前資格輪次已成功進場且未失效即可回報兌換 | 是否必須仍在場內未指定；以可配置的前置條件隔離，不硬寫在 UI |
| A-008 | 每次重刷達標沿用下一個 04:00 可投入 | 第一版一致規則，實際例外可調整 |
| A-009 | 一張卡片一位主要操作者；一筆有效活動 | 操作者可交接，其他人仍能編輯，避免分流意義不明 |
| A-010 | 野外預約與占用不自動逾時釋放 | 無法由網站連線判斷遊戲實際位置 |
| A-011 | 編輯提示約每 10 秒更新、約 30 秒無心跳清除；版本校對約 15 秒 | 可配置的工程初值，實測網路及背景分頁節流後校正；不影響持久占用 |
| A-012 | 第一版單一 Web 實例 | 約 4–5 位使用者無需 Redis；未來多實例須替換在線狀態與通知設施 |
| A-013 | Desktop 首版以唯讀精簡面板為主，完整編輯開啟 Web | 降低首版視窗整合範圍，仍保留未來快速操作入口 |
| A-014 | 所得採增量回報，另有累積值更正 | 避免多人各自覆寫總數；累積包含兌換收入 |

## 3. 尚未指定、不得猜成固定機制的內容

- 實際遊戲伺服器時區是否與 `Asia/Taipei` 一致。
- 各職業的等級、任務道具與功勳門檻；死亡及 TK 判定門檻。
- 兌換是否僅允許仍在活動中、是否有額外每日額度或整批限制。
- 重刷後等待規則是否有不同於首次投入的例外。
- 實際分流編號的唯一範圍、命名方式及是否會跨場次重用。
- 桌面使用者的 Windows 版本、螢幕縮放、遊戲顯示模式與快捷鍵衝突。
- 最終產品名稱、視覺風格與術語，由使用者及設計朋友設定。

上述資訊以設定、可替換政策或手動結果回報處理；不阻擋先完成帳號區域協調功能。

## 4. 明確取代的舊提案

| 舊提案 | 本版處理 |
| --- | --- |
| Blazor 為主、SQLite | 改為 ASP.NET Core＋Vue＋PostgreSQL |
| 每日每角色只能一區 | 移除；只保留當下同帳號同區限制 |
| 完整 Identity 帳密登入 | 改為無密碼暱稱工作階段 |
| 帳密遮罩／加密欄位 | 使用者明確要求取消，按普通文字處理 |
| 人人都能看操作日誌 | 只有暱稱 Admin 可以讀取 |
| 每位訪客都顯示在線／編輯 | Admin 不顯示，普通參與者維持 |
| 只有無值標籤 | 改為帶值欄位；純標記仍是可選型別 |
| 一整包卡片 JSON 一起覆寫 | 自訂值改為欄位級版本及寫入，降低編輯互相覆蓋 |
| 直接以目前功勳推導參與資格 | 以資格輪次保存里程碑，兌換後不誤撤銷已啟用資格 |
| 達標後立即投入 | 等待工作區下一個 04:00 |

## 5. 變更紀錄格式

新增決策時記錄日期、來源、變更原因、受影響的 FR／AC 編號，以及是否需調整既有資料。顯示名稱的小改動是設定資料；核心規則改動才更新此文件與相應測試。
