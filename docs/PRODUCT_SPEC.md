# 產品需求規格

版本：1.0　｜　基準日期：2026-09-09

本文整理對話中已定案的需求。以遊戲名詞說明使用情境；程式碼採中性名稱。尚未由使用者指定的數值或細節，集中標註於 [DECISIONS.md](DECISIONS.md)，不得誤當成已查證的遊戲機制。

## 1. 目標與優先順序

系統供約 4–5 位熟識使用者，共同管理自己與朋友的帳號、角色及相關資訊。

優先順序：

1. 正確呈現帳號與角色的共用狀態，阻止同帳號同時占用不同野外區域。
2. 多人資料同步、可辨識的編輯狀態與衝突處理。
3. 以拖曳、帶值標籤及表格降低填寫負擔。
4. 名稱、欄位、流程、視圖可調整，方便其他用途。
5. Windows 懸浮面板，持續顯示重要狀態。

靈活設定不能解除第一項限制。第一版不需要完整試算表公式引擎、任意使用者程式腳本或全功能流程設計平台。

## 2. 核心狀態規則

### FR-001：同帳號共用資源限制

在同一工作區內，每個帳號有自己的占用範圍。任一時刻，其有效預約與實際占用所指向的**不同野外區域數量不得超過 1**。

- 同帳號多張卡片可以同時進入 A 區。
- 任一卡片仍預約或位於 A 區，其他同帳號卡片就不能預約或進入 B 區。
- A 區還有其他卡片時，第一位進入者回村不會解除整個帳號的限制。
- 全部占用與預約解除後，可以選擇另一區域。
- 不同帳號獨立判斷，可以同時位於不同區域。
- 沒有「每角色每日只能選一區」或「每天帳號固定一區」的規則。
- 切換日期、改卡片標籤、改名、Admin 模式，均不會解除這項限制。
- 所有操作介面及 API 都必須使用同一套後端規則；前端變灰只是提示。

### FR-002：預約、實際位置與解除

初始流程為「選取目的地並預約 → 遊戲中進入 → 回報已進入 → 實際回村 → 回報已回村」。

- 預約成功後立即參與 FR-001 的限制，避免兩個人同時準備去不同區域。
- 只有後端保存成功，前端才能顯示預約成功。
- 尚未進場的預約可以取消；實際占用必須透過回村／離開確認解除。
- 對仍在 A 區的卡片直接選 B 區，必須要求先確認回村。
- 過期資料、關閉網站、電腦睡眠、斷線、切成未使用、封存要求或 04:00 換日，都不能自動解除占用。
- 連線中斷只代表通報可能過期，不代表遊戲角色已離開。
- 需更正錯誤通報時，提供明確的狀態修正操作並留下紀錄；仍不得創造同帳號異區占用。
- 預約與占用必須持久保存，後端重新啟動後仍存在。第一版不做自動逾時釋放。

### FR-003：固定識別與規則綁定

- 帳號、卡片、區域、階段、欄位、標籤、視圖均有穩定 ID。
- 顯示名稱可修改；關聯、規則、歷史、網址及事件均不使用顯示名稱當主鍵。
- 「前往區域」可以呈現為帶值標籤，但必須綁定正式資源 ID 與占用操作。
- 核心綁定欄位的值是正式狀態的投影，不額外保存一個互相矛盾的自由文字值。
- 改名、刪除標籤外觀或隱藏欄位，都不能清除正在生效的占用。必要操作必須仍有固定入口。
- 自訂文字欄位即使也取名為「區域」，也不會自動取得核心規則含義；設定頁應顯示是否綁定正式狀態。
- 帳號表與卡片使用同一個帳號 ID，不因擁有者、別名或視圖不同而複製成不同占用群組。

### FR-004：狀態面向分離

| 面向 | 範例 | 生命週期 |
| --- | --- | --- |
| 帳號擁有者 | 朋友甲的帳號 | 長期資料 |
| 目前操作者／使用狀態 | 使用者乙正在操作卡片甲 | 手動指定與交接 |
| 在線／編輯狀態 | 使用者丙正在編輯職業欄位 | 短暫連線狀態 |
| 流程階段 | 練等、任務、功勳、正式活動 | 卡片流程 |
| 資源占用 | 預約 A、位於 A、已解除 | 明確通報 |
| 參與資格 | 累積中、等待換日、可參與、已啟用、需重刷、永久失格 | 資格輪次 |
| 本次活動 | 分流 3、進入時間、是否已離開 | 一次參與紀錄 |
| 卡片生命週期 | 使用中資料／已封存 | 長期資料 |

編輯卡片不會自動接管角色。初版一張卡片可顯示一位主要操作者，提供明確交接；這不妨礙其他人編輯其資料。Admin 接管時仍顯示卡片使用中，但隱藏操作者身分。

## 3. 可配置資料與介面

### FR-005：帶值標籤

標籤本質為自訂欄位，可在卡片上呈現成「名稱：值」。同一份欄位定義供表格、卡片及面板使用。

必要型別：文字、整數／數字、單選、多選、核取方塊、日期、日期時間、資料關聯，以及無值的純標記。

| 模式 | 適用範圍 | 值的保存 |
| --- | --- | --- |
| 個別標籤 | 手動掛上的卡片 | 各卡片獨立 |
| 共通標籤、獨立值 | 指定資料集的所有卡片 | 各卡片獨立，初始為空值 |
| 共通標籤、共用值 | 指定資料集的所有卡片 | 共用一筆值，一處更新全部同步 |

- 預設共通標籤採「所有卡片都有欄位、各自填值」。
- 初始共通作用範圍是工作區的主卡片資料集，涵蓋所有帳號的角色；不自動加到帳密表或其他自由表格。
- 共通定義即時生效，未來建立的卡片也自動顯示，不逐張複製定義。
- 刪除個別標籤只移除該卡片的掛載與目前顯示；刪除共通標籤則從其適用卡片移除。
- 歷史操作可保留刪除前的名稱及值；刪除不代表抹除既有操作紀錄。
- 修改名稱、顏色、選項順序不會重建欄位 ID。
- 欄位型別變更須檢查原資料；仍被規則引用的定義需先重新綁定才能停用。
- 核心狀態可改外觀名稱，但不能透過刪除標籤繞過 FR-001。
- 空值與數字 0 必須區分；單選值用選項 ID，避免選項改名使資料斷開。

### FR-006：設定頁、視圖與自由表格

所有一般協作者可以調整下列共用設定：

- 工作區名稱、分頁名稱、卡片稱呼、標頭、欄位名稱、階段名稱。
- 欄位型別、選項、顏色、順序、必填及共通範圍。
- 看板欄位、表格欄位、篩選、排序、分頁順序與顯示方式。
- 支援範圍內的流程階段、轉換及規則參數。

第一版提供表格、看板、簡易儀表板與精簡面板。初始分頁包含帳號、總覽、練等、任務、功勳、正式活動、設定，以及可新增的其他表格。上述顯示名稱都可調整。

這些視圖共用同一份資料，跨分頁移動卡片不會複製卡片。提供按鈕／選單移動作為拖曳的替代操作。

使用者可以新建自由表格，例如帳號狀態紀錄或其他備忘資料。每個資料集有自己的欄位與視圖；支援與帳號或卡片建立關聯。第一版不實作任意公式、巨集、跨表任意 SQL 或無限制的網頁版面編輯器。

視窗位置、大小、個人篩選、面板顯示欄位及聲音屬個人偏好，不因其他人的調整而改變。

## 4. 初始流程與數值

### FR-007：養成與任務

初始流程為練等 → 轉職任務 → 累積功勳 → 正式活動。卡片可以依設定移動，後端驗證必要的條件。

- 練等目標及職業是設定與資料，不寫死在類別或元件名稱中。
- 任務通常需要 2–3 天，依職業不同；記錄已取得道具數量即可，目標量可配置。
- 不把任務天數固定成必須通過三個日期欄位。
- 功勳通常累積 5–10 天，僅需最後確認的功勳值，不要求記錄每次勝負。
- 階段完成與實際所在地獨立；移動到另一階段不能默認角色已回村。

### FR-008：04:00 換日與投入資格

已確認：達到資格後需等到下一個遊戲日才能投入，遊戲每日 04:00 換日。

- 以工作區時區的 04:00 計算遊戲日期，後端保存 UTC 時間。
- 初始時區預設 `Asia/Taipei`（UTC+08:00），這是待部署核對的預設值，不是使用者已明確確認的遊戲時區。
- 若達標時間小於當日 04:00，下一個遊戲日從當日 04:00 開始。
- 若達標時間等於或晚於當日 04:00，下一個遊戲日從次日 04:00 開始。
- `EligibleFrom` 是嚴格晚於 `QualifiedAt` 的下一個換日邊界；恰好 04:00 達標須等待下一日 04:00。
- 例：2026-09-09 03:59:59 達標 → 2026-09-09 04:00 可投入。
- 例：2026-09-09 04:00:00 達標 → 2026-09-10 04:00 可投入。
- 不以「滿 24 小時」代替換日，不以使用者筆電時鐘判定資格。
- 資格紀錄保存達標時的時區、換日設定與門檻快照；後續調整設定不默默改寫既有資格。
- 時間到達後可參與的判斷在後端執行，不依賴定時工作或瀏覽器一直開啟。

### FR-009：功勳、資格輪次與重刷

可兌換的剩餘功勳與參與資格分開管理。

- 保存目前確認的功勳值，以及目前這一輪的達標／可投入／已啟用／失效狀態。
- 達標後保留資格里程碑；實際進入正式活動後，該輪記錄為已啟用。
- 兌換扣除功勳，不會自動撤銷已啟用的參與資格。
- 回報「死亡過多、需要重刷」時明確使該輪失效，退回累積階段；保留等級、轉職成果、歷史與累積金幣。
- 重刷後初版沿用下一個 04:00 才可投入的規則；若遊戲另有例外，透過設定與案例調整。此為實作預設。
- 不猜測死亡或 TK 次數門檻。第一版使用者回報結果，已知門檻日後再配置。
- TK 永久失格採持久旗標，不能靠改功勳、標籤、階段或暱稱恢復。
- 舊卡片可以封存，從一般看板移除；若仍占用區域，先確認回村；若仍有活動，先結束或更正活動紀錄。
- 新卡片是獨立資料，可關聯接替對象；裝備交接用備註／欄位即可，無須裝備管理模組。新卡片不繼承舊卡片的累積金幣或資格。

### FR-010：每卡片累積金幣與 1:1 兌換

已確認：只記錄累積取得量；每張角色卡片獨立計算。成功進入正式活動後，可將功勳以 1:1 換成金幣。

- 累積金幣包含回報的活動所得及已回報的功勳兌換所得，不是目前持有餘額。
- 購買裝備不扣除累積金幣，第一版不記錄支出或裝備內容。
- 提供「記錄所得」與「記錄已完成兌換」操作。系統不實際操作遊戲兌換。
- 初版採手動輸入兌換量，支援部分兌換；不在入場時自動兌換全部。
- 一次兌換量需大於 0，且不得超過目前已確認的可兌換功勳。
- 同一交易完成剩餘功勳扣除、累積金幣增加及操作紀錄。
- 同一個請求重送不得重複計算；兩個人同時兌換不能透支功勳。
- 必須有目前資格輪次內的成功入場紀錄，且資格未失效；第一版以此作為「進入後可以兌換」的判定。是否必須仍在場內尚未指定，見決策文件。
- 範例：剩餘功勳 1,000，累積金幣 200，記錄兌換 300 → 剩餘功勳 700、累積金幣 500、已啟用資格維持。
- 累積值若需修正，走有版本檢查的更正操作並留下原因，不能當成負數收入任意寫入。

### FR-011：分流與活動時間

- 「卡片放在正式活動區」不代表已進入某個分流。
- 每次參與保存卡片、操作者、分流、進入時間與是否已結束。
- 分流及進入時間一次提交，避免朋友看到混搭的兩筆狀態。
- 自動帶入伺服器收到回報的時間；允許補填實際進入時間，保留原記錄時間與更正痕跡。
- 對外顯示工作區時區、24 小時制、到秒；跨日需要顯示日期。
- 同一卡片初版只有一筆目前有效的活動；新的一場不覆寫成上一場的延續。
- 結束活動後不再將舊分流顯示為目前位置。斷線則標為資料可能過期，不自動當成已退出。
- 第一版只回報已進入時間；未來如需排隊時間，另設獨立欄位。
- 分流是活動內的資訊，不自動套用野外同區限制。初版限制只針對已確認的野外資源範圍。

## 5. 使用者、Admin 與日誌

### FR-012：暱稱入口

- 系統不設登入密碼。訪客輸入暱稱即可進入。
- 伺服器建立固定參與者 ID 與工作階段，以受保護 Cookie 辨識，不直接採信前端傳入的操作者 ID。
- 一般協作者的資料與設定權限一致，不需要註冊、邀請審批或完整角色管理介面。
- 保留成員與角色擴充位置。第一版唯一特別的能力是 Admin 可讀日誌與隱身。
- 同名不同瀏覽器不自動合併身分。普通同名參與者以代表色或短碼區分。
- 同一工作階段的多個分頁合併呈現在線人員；桌面 WebView2 的登入儲存與普通瀏覽器獨立。

### FR-013：Admin 專屬日誌

- 暱稱為 `Admin` 的工作階段可以看操作日誌，其他工作階段看不到。
- 初版以去除前後空白後、區分大小寫的精確比對判定；`admin`、`ADMIN` 為普通暱稱。
- 伺服器計算能力，日誌 API、搜尋、詳情、下載及推播均驗證該能力；不只隱藏選單。
- 這是暱稱約定：任何能進入私人工作區並輸入 `Admin` 的人都取得此模式，不設額外密碼或身分驗證。
- 修改暱稱走後端並更新目前工作階段能力；改離 Admin 後不能保留舊的日誌存取。

### FR-014：Admin 隱身

- Admin 不出現在其他人的在線名單、人數、編輯提示、游標、焦點標示與加入／離開通知。
- 普通使用者的 API／事件不得取得可用於還原 Admin 活動的操作者 ID、暱稱或最後編輯者等中繼資料。
- Admin 的資料變更仍正常同步；占用、使用中、分流與資格仍反映真實共用狀態。隱身不造成私有分支或忽略衝突。
- Admin 操作卡片時，其他人只看到必要的狀態，例如「使用中」，不顯示其身分，也不顯示「隱身管理員正在操作」。
- Admin 編輯造成的欄位版本衝突仍正常處理，對普通使用者以「資料已更新」提示，不揭露操作者。
- Admin 不產生具名操作通知；最新資料可以直接更新。
- Admin 的操作仍保存於只有 Admin 能看的日誌。隱身是呈現與回應投影政策，不是停止記錄。
- 此約定適用系統產生的活動與身分資訊，不會修改使用者自行輸入的表格文字。

### FR-015：帳號密碼表明文

使用者已明確選擇把帳密當作一般試算表資料：

- 網頁直接顯示文字，不遮罩、不增加揭露按鈕或第二道密碼。
- 資料庫直接保存欄位原文，不做此欄位的應用層加密。
- 所有一般協作者均可依同等資料權限查看及編輯。
- 帳密表、卡片所屬帳號及帳號狀態使用同一個帳號身分。
- 不把正式帳密寫入 repository、測試種子、CI 記錄或示範截圖。
- 操作日誌可寫「某人更新了某帳號的密碼」，不必複製密碼值；不影響帳密表的明文顯示。
- 私人 HTTPS／Tailscale 與工作階段 Cookie 仍正常使用；明文欄位不等於移除傳輸或工作階段保護。

### FR-018：口語操作日誌

- 記錄誰、何時、對哪個元素、做什麼操作，必要時附前後值與原因。
- 保存結構化事件及當時的名稱快照，產生繁體中文口語描述。
- 名稱改動不破壞事件關聯，也不讓過去事件無法理解。
- 一般持久資料操作與日誌於同一交易提交；不記錄每次按鍵、滑鼠移動或短暫在線心跳。
- Admin 行為也記錄；日誌只透過 Admin 能力開放。

範例：「小明把卡片甲的『職業』從『法師』改為『戰士』」、「小林將卡片乙移到『任務區』」、「Admin 回報某卡片已回村」、「小林記錄兌換 300 功勳，累積金幣增加 300」。

## 6. 多人協作與離線

### FR-016：在線編輯與欄位衝突

- 顯示普通參與者的在線狀態、正在查看的卡片、正在編輯的欄位或表格儲存格。
- 編輯存在感與保存分開：輸入草稿先留本地，提交成功後同步已保存值。
- 不同欄位可獨立保存；相同欄位採版本檢查，保留本地草稿並顯示最新值，不無聲覆蓋。
- 看板拖曳也有版本檢查，過期操作必須重新評估。
- 短暫編輯狀態以心跳及逾時清除；清除只影響提示，不能釋放 FR-002 的業務占用。
- Web 與桌面面板共用更新機制；Admin 按 FR-014 過濾。

### FR-017：斷線、重新連線與資料恢復

- 明顯顯示同步正常、重新連線中、資料可能過期。
- 斷線時停用會改變占用、資格、兌換或活動狀態的操作；可以保留尚未保存的一般草稿。
- 不在離線時先假裝成功，或重連後靜默補送進場／兌換等高影響操作。
- 重連取得最新完整快照及版本，再恢復編輯；訂閱／取快照之間不可漏掉更新。
- SignalR 通知不是唯一真相；另以版本校對補捉通知遺漏，聚焦與重連時均重新核對。
- 斷線前未知結果的請求以相同請求 ID 查詢／重試，不能換新 ID 重複計算。

## 7. 桌面與部署

### FR-019：Windows 精簡面板

- WPF＋WebView2 顯示既有 Vue 精簡視圖。
- 第一版提供置頂、移動／調整大小、記住位置、篩選卡片、系統匣、顯示／隱藏快捷鍵。
- 顯示使用狀態、帳號占用、分流／時間、所選欄位、共通標籤與同步時間。
- 點選可開啟完整網站。滑鼠穿透、透明度與更多快捷操作可在後續迭代加入。
- 桌面端不啟動自己的資料庫或後端，不保存另一套核心規則。
- Admin 的隱身與資料投影在桌面端同樣生效。
- 視窗化／無邊框模式為首要驗收目標；獨佔全螢幕覆盖效果需實測，不能保證所有遊戲模式都相容。

### FR-020：技術、環境與交付

- 採用 README 所列技術；單一 repository、單一 Web 發布單位及 PostgreSQL。
- Code-First Migrations 管理實體 schema；使用者自訂欄位是資料，不為每個欄位產生資料庫 migration。
- 核心規則置於可測試的 Domain／Application，介面不能直接繞過規則寫資料庫。
- 私人筆電只開網站或遠端；預覽與正式服務放家中常開電腦。CI 使用獨立測試資料。
- 預覽／正式資料庫分離；部署、migration、備份與還原均有可重現流程。
- 沒有要求此階段建立 Firebase、公開網站或微服務。

## 8. 初始使用流程

1. 進入私人網站，輸入暱稱；若為 Admin，按隱身與日誌規則處理。
2. 定義名稱、欄位與共通標籤；之後由朋友持續調整用語與呈現。
3. 建立帳號與卡片，填入所屬關係、職業與各標籤值。
4. 選擇當前卡片，設為正在使用並記錄操作者。
5. 選取野外目的地、取得預約，再回報實際進入；完成後確認回村。
6. 完成練等後移入任務區，更新已取得道具數量。
7. 完成任務後移入功勳區，更新最後功勳值。
8. 達標後等待下一個 04:00，資格到期可投入正式活動。
9. 記錄分流與實際進入時間，朋友從網站／面板查看。
10. 記錄活動所得或已完成的功勳兌換，更新該卡片的累積金幣。
11. 必要時回報重刷功勳；永久失格則結束占用及活動後封存，另建新卡片。
