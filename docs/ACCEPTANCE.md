# 驗收案例與測試計畫

版本：1.0　｜　所有案例目前為「待實作／待驗證」，不是已通過的測試報告。

每次交付在 PR 中列出實際執行的案例編號與結果。使用虛構帳號與卡片；下列數值只供測試，不代表遊戲實際門檻。

## 1. 測試層級

| 代號 | 方法 |
| --- | --- |
| U | xUnit 純領域測試，Clock 可替換 |
| I | 真正 PostgreSQL＋Application／API 整合測試 |
| V | Vitest 元件／前端資料狀態行為測試 |
| E | Playwright 多瀏覽器工作階段端到端測試 |
| W | Windows 桌面人工或適合的自動化驗收 |
| O | 發布、備份、環境等操作驗收 |

並行案例以獨立 DbContext／資料庫連線，使用 barrier 或等價方式讓請求交錯；不能先執行完第一筆才送第二筆。測試實際 API 路徑與後端規則，不只測假物件。

## 9. 執行與證據

- 初版最先落地 AC-001–AC-014，並把 AC-008 設為核心合併檢查。
- 後續依里程碑加入案例，不為尚未開發的功能製造必定失敗的 CI。
- 保存必要的測試報告、失敗截圖與 Playwright trace；資料一律虛構。
- UI 可視結果、資料庫最終狀態與真正同時請求要對照，不能只看 toast 或 HTTP 成功碼。
- Desktop／遊戲覆蓋的人工驗收不可由「Web 測試已通過」代替。
- 沒有執行的案例註記未驗證及原因；不將本表自動全勾為完成。
